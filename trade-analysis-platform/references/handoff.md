# 交接状态与继续开发方法

## 先做现场复核

本文件是交接导航，不替代当前工作区检查。接手时先执行：

```bash
cd /Users/ken/work/贸易分析平台/platform
git status --short --branch
git log -5 --oneline
rg --files frontend/src data-ingestion .github/workflows | sort
```

当前项目曾持续迭代晨报、潮汐早报、地球仪、出口条件、风险、成本计算器、数据健康中心和模板库；存在用户未提交修改时，先分清“本次任务”与“已有工作”，不要清理或回滚后者。

## 已形成的开发风格

- 先建立数据契约和质量审计，再接 UI；前端不直接跨域抓取外站。
- 以可追溯快照驱动图表，来源、截至时间、覆盖期和 fallback 状态在适当位置可见。
- 复杂信息优先通过联动、折叠、分栏和详情层组织；避免“大图占屏但无法滚动”和全部内容平铺。
- 视觉上追求中文信息产品的精致克制：浅色主体、局部暗色地球、钢蓝与暖金层级、清楚的单位和口径。
- 所有自动生成文本都必须从实际指标、词库和规则来，不能为了连贯而补造事实；无匹配项直接省略无意义占位。

## 潮汐早报接手重点

潮汐早报抓取链路涉及 Kagi 五板块、正文详情、图片、历史上的今天、翻译和 Actions。普通板块有记录，不能推断历史人物/事件已经抓取；需要单独查看 `external_tide_news.json` 的分类计数、图片字段、详情字段和快照质量。若源站 SSR/客户端结构变化，优先更新解析器和 fixture/诊断输出，再改组件。详情阅读层必须把滚动容器放在展开窗口内部，不能要求用户把光标移到侧边。

## 当前风险判断方法

- 不把旧快照称为实时；以 `data_sync_status.json` 的状态和覆盖日期为准。
- 不把配额缺失、救济案件缺失或历史出口为零混成同一个分数。
- 不把海关全市场出口与内部公司业务直接求和；并列展示时明确统计口径。
- 不把来源页的“导出 Excel”当成自动化 API，除非实际验证了稳定下载入口和授权。

## 建议的继续顺序

1. 先运行 smoke/build 和相关审计，确认当前基线。
2. 如果是数据任务，先复核源站、输出快照和失败保留逻辑，再接 Provider。
3. 如果是 UI 任务，先定位页面组件和 CSS 作用域，使用真实快照验证 loading、空态和 fallback。
4. 如果是动效任务，按照 [ui-motion.md](ui-motion.md) 做 reduced-motion、触控和卸载验收。
5. 最后按 [quality-release.md](quality-release.md) 运行验证并给出限制；发布动作等待用户明确授权。

## 与 Claude Code Sonnet 沟通的最小任务格式

建议每次说明：

```text
目标：要新增/修改/删除什么
范围：允许改哪些路由、数据源或文件；明确不能影响什么
数据：来源、快照/实时要求、统计口径和缺失时行为
体验：桌面/移动端、交互、动效和无障碍要求
验收：必须看到的页面结果、命令、数据数量或状态
发布：仅本地、提交，还是明确推送/部署
```

交接完成不代表所有来源都能访问；每次报告都应区分代码已完成、快照已生成、调度已配置、线上已发布这四种状态。
