# 贸易沙盘模拟验收标准

## 范围

本标准只验收 `#/trade-sandbox`。原有 `#/globe`、`#/globe-lab`、晨报、综合分析、成本计算器、运输方案和销售方案必须保持原有行为。

## 可复现验收清单

1. 打开页面后，必须能看到“贸易沙盘模拟”，并显示 `215 个可识别国家`、内部业务国家数量和已定位标注数量；国家边界来自 `world.json`，不以内部业务是否存在作为可识别条件。
2. 首屏必须同时出现 3D 地球、图层开关、推演控制台、贸易操作配置、目标市场和风险/流向反馈；地球为独立 WebGL 实例。
3. 风险层、事件层、贸易流向层可独立开关；关闭残余矛盾层时，只隐藏残余线路，不改变其他流向和计算结果。
   默认不铺满全局线路；选择目标国家后仅显示对应线路，未选目标时手动打开“选定线路”最多显示 16 条主线路。国家面、彩色点位、脉冲环和右侧指标始终承担全局关系反馈。
4. 推演变量必须支持贸易救济、配额松紧、区域政策、金融局势、航运要道、航运价格六项，并分别支持缓解/放宽/下降与收紧/升级/上升两种方向。
5. 切换变量或方向后，推演标题、推演后流量、受影响目的国、残余矛盾和模拟流向列表必须同步变化；一次只激活一个变量。
6. 修改订单规模、策略取向、品类权重或目标市场后，模拟流量必须重新计算。编辑值只写入 React 状态和沙盘本地方案，不回写原始业务 JSON。
7. 点击目标市场列表中的国家后，该国家变为“已选”，地图镜头聚焦并出现高亮/脉冲环；再次点击可以移除。地图国家悬停提供高亮和基础提示，点击可加入目标市场。
8. 风险/政策/配额标注必须能回到真实快照中的国家记录；没有国家字段或没有边界匹配的全局风险不得伪造地图点位。
9. 保存方案后，方案进入最近 8 套本地复盘记录，刷新页面仍可读取；重置后配置、目标市场和变量回到真实基线。
10. 对 `prefers-reduced-motion: reduce`，GSAP 和 Globe.gl 的持续动画降级，页面仍可操作。

11. 国家边界完整性：加载 `world.json` 后，所有具名 Polygon / MultiPolygon 均应进入地图；仅移除非法坐标环，不对坐标做简化。当前快照基线为 215 个可识别国家边界，另有 2 个无名称几何不冒充国家。
12. 国家面可读性：无业务国家不得使用接近背景的单一灰色；无业务、已接入业务、存在政策/配额、存在救济分别使用可辨识色阶，悬停/选中使用高亮和上浮。
13. 数据映射：业务量越大，业务点位高度/半径和出口弧线粗细随归一化值变化；弧线颜色区分正向（+）与负向（-）；风险标注水波半径和速度随影响等级变化。
14. 影响表达：不以吨数直接宣称影响精度。所有推演流向和风险标注均显示 1–5 级及文案——1级“几乎无影响”、2级“轻微影响”、3级“中度影响”、4级“显著影响”、5级“剧烈影响”，并显示正向（+）/负向（-）。
15. 全量国家检索：默认展示业务量前 10 个国家；输入国家名或英文名可检索全部具名边界。无内部业务快照的国家仍可点击、聚焦、加入目标市场，并显示“暂无内部快照”，不得被误判为不可检索。
16. 交互稳定性：操作订单、变量、图层、目标市场和拖动地球时，WebGL Canvas 始终为 1；不得调用 `_destructor()` 后重建地球，不得出现镜头闪回或连续跳动。

## 工程门槛

- `cd frontend && npm run type-check` 通过。
- `cd frontend && npm run build` 通过。
- Impeccable detector 对沙盘 TSX/CSS 返回空问题列表。
- 桌面端不得出现横向滚动；窄屏按单列堆叠，侧栏从固定高度滚动区降级为页面流。
- 原有路由至少抽查 `#/globe`、`#/globe-lab` 和 `#/` 能正常打开。
